# Speech Bubble System — Beginner's Guide

*For Carmaniac's (Lostsoulsdev's) Speech Bubble script, V3.0.2 — Essentials V21.1*

This guide explains how to make events and the player show speech bubbles, thought bubbles, and shocked reactions in your game. It covers the old method (still fully supported) and the new, easier methods added on top of it.

---

## 1. The Basics — Bubble Types

Every method below asks you to pick a "window type." This is just a number from 1 to 4 that decides what the bubble looks like:

| Number | Bubble type |
|---|---|
| 1 | Floating bubble |
| 2 | Speech bubble with an arrow |
| 3 | Short arrow window |
| 4 | Shocked window |

Keep this table handy — you'll use these numbers in almost every script call.

---

## 2. The Original Method (still works)

This is the classic way of doing things. Nothing about it has changed, so any old events you've already built will keep working exactly as before.

**How it works:** before every "Show Text" command in your event, add a script call:

```
pbCallBub(WindowType, EventID)
```

- `WindowType` — the bubble number from the table above (1–4)
- `EventID` — the ID number of the event that's talking

**Example:** you want Event 10 to talk using a floating bubble:

```
pbCallBub(1, 10)
```

You'd place this script call directly above the Show Text command in that event's page.

**The catch:** if your event has several Show Text boxes in a row, you have to repeat this script call before *every single one*. That's what the newer method below fixes.

---

## 3. The Easier Method — `pbSpeech` (recommended for new events)

This does the same job as `pbCallBub`, but it's smarter about events with multiple lines of dialogue. Use this one going forward instead of the old method.

```
pbSpeech(WindowType, EventID, KeepAlive)
```

- `WindowType` — the bubble number (1–4)
- `EventID` — the ID of the talking event
- `KeepAlive` — `true` or `false` (explained below)

### What `KeepAlive` does

If your event has multiple Show Text boxes back-to-back, you don't want to insert this script call before every one. Instead:

1. Before the **first** Show Text, call it with `true`:
   ```
   pbSpeech(1, 10, true)
   ```
   This tells the script "Event 10 is the one talking right now — keep the bubble active until I say otherwise."

2. You can now have as many Show Text boxes as you like without repeating the call.

3. Right before the **last** line of dialogue (or when you're switching to a different speaker), call it again with `false`:
   ```
   pbSpeech(1, 10, false)
   ```
   This tells the script "Event 10 is done talking — stop treating it as the active speaker."

**Quick way to remember it:** `true` = "start talking," `false` = "stop talking."

---

## 4. New Feature — Floating Speech Bubbles

This is a completely new feature that lets events (or the player) show a bubble that floats above their head, without pausing the game or blocking movement. Great for ambient chatter, thought bubbles, "!" reactions, and so on.

There are two ways to trigger one: through an **event comment**, or through a **script call**. Both use the same options — pick whichever fits how you build your events.

### 4a. Using an Event Comment (easiest for most people)

Add a comment inside your event that looks like this:

```
pbSpeechBubbleShow(EventID, "Text")
```

- `EventID` — the event that should show the bubble. Use **-1** to target the player instead of an event.
- `"Text"` — whatever you want the bubble to say, in quotes.

**Example — make the player show a thought bubble:**

```
pbSpeechBubbleShow(-1, "Ooops")
```

This bubble will follow the player around as they move.

### 4b. Extra Options

You can add more detail to the same call. These options are optional, but here's what each one does:

| Option | What it does | Example |
|---|---|---|
| A number (seconds) | Bubble automatically disappears after this many seconds | `pbSpeechBubble(-1, "Ooops", 3)` → disappears after 3 seconds |
| `:F` | Makes the bubble fade in and out smoothly | `pbSpeechBubble(10, "Help!", :F)` |
| `:A` | Makes the bubble automatically move out of the way of other bubbles on screen | `pbSpeechBubble(10, "Help!", :A)` |
| `:Shock` | Shows an animated "shocked" bubble instead of a normal one | `pbSpeechBubble(10, "Help!", :Shock)` |
| `:Max => Tiles` | Only shows the bubble while the player is within a certain number of tiles of the event | `pbSpeechBubble(-1, "Ooops", :Max => 4)` |

**Important rule:** if you use `:Max => Tiles`, it must always be the **last** thing in the brackets, or the script will behave oddly. Put every other option before it.

**Example — bubble that only appears when the player is close:**

```
pbSpeechBubbleShow(-1, "Ooops", :Max => 4)
```

This will only show "Ooops" above the player while they're within 4 tiles of the event (in any direction). Walk away, and it disappears automatically. Walk back, and it reappears.

**Example — combining several options:**

```
pbSpeechBubble(10, "Help!", 3, :F, :Shock)
```

This shows a shocked, fading-in bubble saying "Help!" above Event 10, and it automatically disappears after 3 seconds.

You can have multiple bubbles on screen at once — just call `pbSpeechBubble` for each event you want to show one. Try not to overdo it, though; too many bubbles at once can look messy.

### 4c. Clearing Bubbles Manually

If you didn't set an automatic timer, bubbles will stay on screen until you clear them yourself. To clear **every** bubble currently showing:

```
pbClearBub
```

## 5. New Feature — Checking Player Distance

Sometimes you just want to know *if* the player is near an event, without necessarily showing a bubble — for example, to trigger a movement or a cutscene once the player walks close enough.

```
pbCheckDist(Tiles, EventID)
```

- `Tiles` — how close (in tiles) the player needs to be
- `EventID` — the event to measure distance from

This returns `true` if the player is within range, and `false` if not.

**Example use case:** put this inside a Conditional Branch, in an event running as a Parallel Process. When the player walks within range, the branch becomes true and can trigger movement, animations, or dialogue.

**A word of caution:** avoid putting this check on too many events on the same map at once — checking distance constantly on lots of events can cause noticeable lag.

---

## 6. Quick Reference Cheat Sheet

```
pbCallBub(type, eventID)                          Old method — call before every Show Text
pbSpeech(type, eventID, keepAlive)                New method — true to start, false to stop
pbSpeechBubbleShow(eventID, "text", options)      Floating bubble via event comment
pbSpeechBubble(eventID, "text", options)          Floating bubble via script call
pbClearBub                                        Clears every bubble on screen
pbCheckDist(tiles, eventID)                       Returns true/false if player is nearby
```

**Bubble types:** 1 = Floating · 2 = Speech bubble with arrow · 3 = Short arrow window · 4 = Shocked window

**Floating bubble options (order matters — `:Max` always goes last):**
- Number = seconds before auto-disappearing
- `:F` = fade in/out
- `:A` = avoid overlapping other bubbles
- `:Shock` = shocked/animated style
- `:Max => tiles` = only show within this many tiles of the player (must be last)
